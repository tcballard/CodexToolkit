# Community Radar report contract

Use these headings for a durable report:

```markdown
# Community Radar

## Product context
## Evidence ledger
## Audience profile
## Community map
## Current conversations
## Opportunity ranking
## Engagement strategy
## Risks and unknowns
## Action plan
## Sources
## Checked on
## Not checked
```

## Required content

### Evidence ledger

Separate `Confirmed`, `Inferred`, `Unverified`, and `Preference` items. Link material repository or product sources.

### Audience profile

For each audience, state role, problem, relevance, evidence state, and confidence.

### Community map

Include community, audience, relevance, observable activity, overlap, norms, evidence, confidence, and access limitations. Rank only included communities; explain exclusions that a user would reasonably expect to see.

### Current conversations

Include direct URL, platform, visible publication/activity date, observed date, paraphrased need, evidence state, and constraints. Do not use static community homepages as conversation evidence.

### Opportunity ranking

Include score, band, confidence, every dimension rationale, and recommended posture. Link the ranked JSON when persisted.

### Risks and unknowns

Consider hostility, moderation, duplicate promotion, launch fatigue, recent competitors, immaturity, missing capability, geographic mismatch, private access, and thin evidence.

### Action plan

Use only relevant horizons: `Today`, `Tomorrow`, `This week`, `Before next launch`, and `Revisit`. Every action must name its evidence or prerequisite. Empty calendar theater is worse than a shorter plan.

### Sources and gaps

Provide direct links near claims and a consolidated source list when useful. Record the ISO checked-on date and exactly what was not checked.
