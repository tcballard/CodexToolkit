# Example decisions

These examples demonstrate reasoning shape. They are not current evidence or reusable channel recommendations.

## OSS launch

An open-source CLI has a stable release and repeated GitHub issues in adjacent projects asking for the same missing workflow. Rank the direct issues only if participation would help maintainers; prefer interoperability guidance or a contribution over dropping the project link. Use Merge & Tell only after the owner chooses a release announcement.

## Startup beta

A private beta solves a recurring operator complaint found in a specialist forum. If the forum prohibits recruitment, recommend answering the operational question without promotion and improving the product's public explanation. Revisit a testing invitation in a permitted feedback community.

## Build Week

A time-bound developer-tool submission has limited maturity. Separate communities that value build logs and technical learning from launch channels. Recommend sharing verified implementation lessons now, completing demo/readiness gates, and waiting to submit a product link until the claimed workflow is demonstrable.

## Developer tool

`last30days` surfaces several recent conversations about agent orchestration. Community Radar re-opens each source, removes broad AI commentary, scores only threads with a concrete workflow problem, and recommends one technical reply plus a documentation article derived from repeated questions. It does not produce the reply or article copy.
