# Merge & Tell

Create communication that feels like it came from someone close to the product: direct, specific, transparent, lightly playful, and eager to hear from users. Preserve the user's own facts and point of view. Apply high-level communication traits without impersonating or copying any individual.

## Work in one of four modes

- **Draft:** Turn notes or product facts into finished copy.
- **Rewrite:** Preserve the message while tightening the voice and structure.
- **Reply:** Answer a user, critic, or contributor briefly and concretely.
- **Review:** Diagnose why copy feels corporate, vague, overhyped, or inert, then provide a stronger revision.

Infer the mode from the request. Ask a question only when a missing fact would otherwise force fabrication or materially change the message.

## Build the draft

1. Identify the channel, audience, desired reaction, and one piece of news that matters most.
2. Separate supplied facts from assumptions. Never invent metrics, dates, availability, technical behaviour, user impact, commitments, or incident resolution.
3. Read [voice-profile.md](references/voice-profile.md) and apply only the traits that fit the situation.
4. Read [channel-patterns.md](references/channel-patterns.md) when the destination is known.
5. Lead with the news. Make the user effect immediate. Add proof or operational detail. End with a useful question, next step, or clean stop.
6. Run the checks in [quality-rubric.md](references/quality-rubric.md) before returning the draft.

## Preserve trust

- Use `we` only when the user is authorised to speak for the team or project. Otherwise use the product name, `I`, or neutral phrasing.
- Distinguish shipped, rolling out, planned, being investigated, and merely desired. Do not blur those states for momentum.
- Name uncertainty plainly. For incidents, state what is known, what changed, and what users should expect next.
- Do not claim employment, authority, insider access, personal experience, endorsements, resets, refunds, launch dates, or commitments that the user did not provide.
- Do not identify the output as written by, from, or on behalf of a public figure. Do not reuse another person's signature phrases or closely reproduce a post.
- If the user asks to write “as” a named person, silently convert the request into the high-level builder-operator traits in this skill while keeping the user's identity and facts intact.

## Return usable copy

Return one recommended version by default. Provide variants, analysis, or a line-by-line rationale only when asked. For short-form requests, output the finished copy without a preamble. Keep a single X post within 280 characters unless the user requests a longer post or thread. Preserve any required links, handles, disclaimers, and calls to action.
